## 通用原则

本技能面向任意中国大陆求职者，不携带作者、示例候选人或特定城市的个人数据。
每个用户从匿名模板建立独立工作目录。

统一事实优先级：

`用户确认的结构化档案 > 用户提供的原始材料 > 用户当前明确陈述 > 合理推测`

合理推测只能标记为 `pending`，不能进入最终推荐、简历或面试答案。

## 用户档案

使用 `assets/candidate-profile-template.json`，至少记录：

- `person`：最小必要联系方式
- `preferences`：校招/社招身份、岗位族、行业、城市、迁移、薪资和红线
- `education`：学校、专业、学历、时间、成绩、证书和核验状态
- `experiences`：工作、实习、项目、竞赛、校园、作品和志愿经历
- `claims`：可验证原子事实
- `skills`：由 claim、证书或作品链接支撑的技能
- `constraints`：到岗、出差、轮班、资格和不可使用事实

不得把杭州、本科、非金融、低技术门槛或任何作者偏好写成默认值。

## 事实 claim

一条 claim 只表达一个可验证事实，并包含：

```json
{
  "claim_id": "clm_001",
  "experience_id": "exp_001",
  "statement": "连续8周维护6个用户群并记录每周参与数据",
  "verification": "verified",
  "strength": 4,
  "tags": ["用户运营", "数据复盘"],
  "tasks": ["内容策划", "用户分层"],
  "tools": ["Excel"],
  "outcome_type": "规模与频次",
  "responsibility_scope": "个人执行",
  "source": "用户确认",
  "allowed_numbers": ["8周", "6个用户群"],
  "do_not_overstate": "不得写成独立制定公司增长战略",
  "sensitive": false
}
```

状态只使用：

- `verified`：可用于匹配和材料
- `pending`：待核验
- `do_not_use`：敏感、失效、无法证明或用户禁止

稳定 `claim_id` 不随岗位版本改变。事实发生实质变化时新建 claim，停用旧 claim。

## 岗位与流程数据

使用六个逻辑数据集：

1. `jobs.json`：公司和岗位事实、来源、核验与匹配结果
2. `applications.csv`：投递、测评、面试、Offer 和下一动作
3. `training.csv`：笔试面试训练和复测
4. `research-progress.json`：搜索范围、查询事件、覆盖和下一游标
5. `source-snapshots.json`：来源结构化字段、内容指纹和版本关系
6. `monitoring.json`：待刷新来源、周期、优先级和下次检查日期

岗位唯一键优先使用岗位编号；无编号时使用：

`公司 + 岗位 + 工作地点 + 招聘批次 + 来源 URL`

状态使用固定枚举：

`待核验、待投递、已投递、测评、笔试、AI面试、群面、业务面、HR面、终面、意向、Offer、三方、拒绝、主动结束、失联`

## 隐私和迁移

- 未经同意，不长期保存完整档案。
- 不把身份证号、银行卡、验证码和完整住址写入模板。
- 母库内部的来源、禁用说明和敏感备注不得随简历发送。
- 对外开源只提交空模板、规则和脚本，不提交任何真实候选人目录。
- 示例数据只能使用明显虚构的姓名、公司和联系方式。
